# Rust v0.2 smoke evaluation

2026-09-20 に Apple Silicon macOS 上で実施。ローカルの `.jrgenv` を自動検出し、TypeSafe の実 API を呼び出しました。応答モデルは `jev-1.13.0` です。

対象は同梱サンプルと、開発中の jrg 自身の Rust ソースです。各ケース1回、既定の前後5行・候補上限200・バッチ上限8を使用し、上位3件を返しました。

| 探す処理 | パターン | 候補数 | 1位 | Noul | API 時間 | 入力 tokens | 候補→返却文字数 |
| --- | --- | ---: | --- | ---: | ---: | ---: | ---: |
| HTTPステータスによる再試行判断（サンプル） | `retry` | 2 | `examples/retry_demo/policy.py` | 0.97 | 629 ms | 779 | 564 → 564 |
| 過負荷応答の待機・再試行 | `429\|retries\|Retry-After` | 6 | `src/jev.rs` | 0.94 | 615 ms | 1,918 | 2,410 → 1,418 |
| 環境変数を優先したAPIキー読み込み | `discover_env_file\|TYPESAFE_API_KEY` | 7 | `src/config.rs` | 0.95 | 518 ms | 2,426 | 3,739 → 1,518 |
| 候補上限と検索打ち切り | `max_candidates\|truncated` | 7 | `src/search.rs` | 0.90 | 664 ms | 2,562 | 4,224 → 1,962 |

サンプルの `metrics.py` は 0.06 でした。Rust ソースの3ケースでも、事前に想定した実装ファイルが1位に来ることを確認しました。

これは小さな自己選択タスクによる疎通・位置特定の確認です。一般的な Recall@K、確率の校正、エージェントのタスク成功率は測定していません。文字数はソース断片だけで、エージェント入力全体のトークン削減率ではありません。API時間も各1回の観測値であり、性能保証ではありません。

再実行例:

```bash
jrg '429|retries|Retry-After' src \
  --about 'API が過負荷やレート制限を返した際、待機して再試行する条件を決める処理' \
  --json --stats --top 3
```

別途、Python プロトタイプの CLI テスト8件を Rust バイナリに差し替えて全件成功しました。Rust の自動テストはローカル模擬 API で実行し、外部サービスの確率変動に依存させていません。
